# Public site (marketing + catalog)

The logged-out, unauthenticated surface: `/`, `/classes`, `/coaches`, `/register`, `/login`, plus the existing `/private-classes` (shipped earlier, CKQ parity Phase 4). Built against a Claude Design handoff (`HANDOFF.md`), corrected in two places against the real codebase before implementation — see "Corrections from the handoff doc" below.

## Hard rule

**Backend is the source of truth; the frontend never derives.** No client-side price math, no seat-count arithmetic, no invented copy. Every rendered number/string on a public page traces to a `GET /*/public` response field. `docs/design-system.md`'s "Public marketing pages" section documents the one exception to the `LoadError`-always rule (the home page renders nothing on a failed section fetch, rather than an error card, since a stranger should never see an error card).

## Backend: `/*/public` endpoints (no auth)

Each existing resource router gets a `/public` sub-route (registered before its own `/:id`), matching the convention already established by `private-class-schedules/public` — **not** a separate `/api/v1/public/*` router, despite what the original handoff proposed.

| Endpoint | Returns |
|---|---|
| `GET /levels/public` | `[{ name, order, monthlyFee }]` — excludes any level with no configured `Price`, rather than showing a missing/invented fee. |
| `GET /locations/public` | `[{ name, address, timezone }]` |
| `GET /group-class-schedules/public` | `[{ className, levelName, locationName, timezone, coachName, dayOfWeek, startTime, endTime, availability }]` — `availability` is `'open' \| 'full'`, server-derived via `groupClassSchedule.service.js`'s `computeAvailability(schedule, groupClass)`. No ids, no roster, no capacity number. `timezone` (added `docs/plans/frontend-polish-plan.md` PR 4) is THIS schedule's own location's IANA zone — the location is already populated for this query, so it's a zero-extra-query field, and `Location.timezone`'s first real consumer (`docs/plans/timezone-consistency-plan.md` D8). |
| `GET /spotlights/public?type=coach\|student` | `[{ name, title, body, bullets, imageUrl }]` — published only, ordered, verbatim strings. Still backs `/coaches`; no longer fetched by the home page (see `TestimonialsSection` below). |
| `GET /testimonials/public` | `[{ quote, authorName, caption, imageUrl }]` — published only, ordered, verbatim strings. Added 2026-08-29, backs the home page's `TestimonialsSection`. |

`computeAvailability` is also now the single implementation used by `subscription.service.js`'s `changeSchedule` capacity check (previously an inline duplicate) and by a **new** guard added to `registration.service.js`'s `create()` — before this work, a class could be overbooked via direct registration because only `changeSchedule` enforced capacity. Registering into a full schedule now returns `409 "This class is full"` before the Stripe charge.

## `Spotlight` model (GAP-2)

Editorial content, admin-authored, deliberately **not** linked to `User` by ObjectId — coupling it to an account row would mean either polluting `User` with marketing fields or auto-publishing a minor's record. Fields: `type` (`coach`|`student`), `name`, `title`, `body`, `bullets` (max 3, validated), `imageUrl`, `isPublished` (default `false`), `order`. Admin CRUD at `/admin/spotlights` (Pattern A, sidebar under a new **Content** section) — see `docs/features/admin.md`.

`imageUrl` can be filled in two ways: pasted directly, or via `POST /spotlights/upload-image` (admin/superadmin, multipart, 5MB cap), which uploads to **Vercel Blob** (`BLOB_READ_WRITE_TOKEN`, provisioned via `vercel blob create-store`) and returns the file's public URL. The stored blob pathname is a random UUID, never the uploader's original filename. `@vercel/blob`'s `put()` has no test-mode equivalent (unlike Stripe) — it's mocked at the module boundary in `spotlight.routes.test.js`, a named exception in `docs/TESTING_STRATEGY.md`.

## `Testimonial` model (added 2026-08-29, replaces Spotlight on the home page)

Same standalone, hand-published pattern as `Spotlight` above — editorial content, not linked to `User`. Fields: `quote`, `authorName`, `caption` (optional, the short handwriting-style line shown under the photo), `imageUrl`, `isPublished` (default `false`), `order`. Admin CRUD at `/admin/testimonials` (Pattern A, same **Content** sidebar section as Spotlights) — see `docs/features/admin.md`. Image upload works identically to Spotlight's (`POST /testimonials/upload-image`, same Vercel Blob mechanism, same test-mocking exception).

Built to replace `TeamBand`/`SpotlightCard` on the home page: comparing a second reference screenshot of the live site's actual "What Families Says" section found it uses real parent testimonials in a polaroid-card marquee, not coach/student bios — and the WP export's own raw data for that section turned out to be unusable leftover multi-sport placeholder text (a swim club, "Coach Jenna", literally "by Placeholder"), the same class of stale-export issue as the hero photo/copy below. Rather than hardcode uncertain screenshot text, this ships as a proper admin-manageable model like Spotlight, seeded with one confirmed real testimonial — the owner adds the rest via `/admin/testimonials`. `/admin/spotlights` and `/coaches` (which still uses coach spotlights) are unaffected.

## Frontend

- **Public nav** (`AppShell`'s logged-out branch): Home, Programs (`/classes`), Our Team (`/coaches`), Private Lessons, Log In, Take a Trial Class. Every public CTA points at `/register` — there is no guest booking (`POST /trial-classes` is parent-only). Labels rebranded 2026-08-29 (`docs/plans/wordpress-ui-alignment-plan.md`, Phase 2) to mirror the live WP site's own nav wording; "Classes"/"Coaches"/"Book a Free Trial" were the pre-rebrand labels.
- **`/classes`**: modeled directly on the pre-existing `/private-classes` page (same `useLoadState` + `LoadError` + grouped-rows shape). Client-side level filter over an already-fetched list (presentation, not invention). Rows grouped by `dayOfWeek` via the shared `DAY_LABELS` constant (`lib/constants.ts` — also now used by `/admin/schedules` and `/coach/schedules`, which each previously declared their own copy). Ends in `SiteFooter` (fetches `/locations/public` alongside its existing data).
  - **Level filter option list** (`docs/plans/frontend-polish-plan.md` PR 4, finding B4) — comes from `GET /levels/public` (already sorted by the admin's own `Level.order`), never derived from whichever schedule rows happened to arrive: a level with zero scheduled sessions still appears, and the order always matches the catalog, never `.sort()`'d alphabetically. Filtering the already-loaded schedule rows client-side against the selected level stays presentation, unchanged. A failed levels fetch degrades the filter to "All levels" only (never a `LoadError`, never a crash — a progressive-enhancement control, not primary content) while the schedule table itself still renders normally from its own, separately-fetched, still-critical data.
  - **Timezone line** (finding B2) — the page no longer guesses a single timezone from `locations[0]`. Each schedule row carries its own `timezone` (see the endpoint table above); when every returned row shares one distinct timezone, the page keeps its single "All times shown in X" line, and when rows span more than one, that line disappears in favor of each row naming its own zone.
  - **Filter control** — a pill-toggle `role="radiogroup"`/`role="radio"` row (same accessibility pattern as the parent-portal flow kit's `PillRow`, reimplemented independently in `shared.module.css` rather than importing a portal-only component into a marketing page) above 600px; the original `<select>` remains below 600px, driving the identical `levelFilter` state.
- **`app/components/marketing/`**: `Hero`, `ValuesMarquee`, `IntroSection`, `ProgramsSection`, `FacilityBand`, `TestimonialsSection`, `StepsRow`, `CtaBand`, `SiteFooter`, `ContactBlock`, one `marketing.module.css`. `ScheduleTable` is shared between `/classes` and `/coaches`'s footer. `SiteFooter` is used on exactly `/`, `/classes`, `/coaches` — never on flow/auth pages (`/register`, `/login`, `/private-classes`).
  - **`TeamBand`** (`align`-agnostic full-bleed navy roster band) and **`SpotlightCard`** (`align="left"|"right"` alternating profile, optional `eyebrow`) are **not rendered anywhere** as of the `/coaches` redesign below (2026-08-30) — kept in place as working, tested, unused components, not deleted. `TeamBand` was the home page's coach teaser until `TestimonialsSection` replaced it (2026-08-29, different content — family testimonials, not coach bios); `SpotlightCard` was `/coaches`'s own layout until the redesign below reused `TeamBand`'s CSS classes directly instead. Either could be wired back in later (e.g. `TeamBand` as a home-page teaser linking to `/coaches`) without new component work.
- **`/register`, `/login`**: both accept `?next=`, which wins over the role-based default landing page (`ROLE_LANDING_PATH` in `lib/constants.ts` — admin/superadmin to `/admin/dashboard`, coach to `/coach/schedules`, parent to `/parent/dashboard`) added so a signed-in visitor never sees an interim "Welcome" screen. So does visiting `/` while already signed in. Both `/register` and `/login` wrap their form in a `<Suspense>` boundary — `useSearchParams()` requires one for `next build`'s static prerendering to succeed.
- **`/coaches`** — redesigned 2026-08-30 to match the live WP site's actual "Our Team" section (owner-provided reference screenshot + the real WP export, not the original handoff's guess): a full-bleed navy band (`OUR TEAM` eyebrow, `Guided by Experience` H1, real WP subcopy, all verbatim owner copy) containing a grid of every published `type: 'coach'` spotlight as a circular-photo card (name + title only — no body/bullets in this layout; `Spotlight`'s `body`/`bullets` fields still exist for a future per-coach detail view). ## Corrections from the handoff doc

The original handoff (`HANDOFF.md`, authored by Claude Design without full codebase visibility) got two things wrong, caught during verification before any code was written:

1. **"There is no public read surface"** — false. `private-class-schedules/public` (no auth) and the live `/private-classes` page already existed. The new `/*/public` endpoints and `/classes` page were built as siblings of that existing pattern, not invented from scratch.
2. **Route shape** — the handoff proposed a new `backend/src/routes/public.routes.js` mounted at `/api/v1/public`. The existing, already-shipped convention is a `/public` sub-route on each resource's own router; the new endpoints follow that instead, to avoid a second parallel convention.

The registration capacity gap (above) was discovered independently while verifying the availability feature, not called out by the handoff.
